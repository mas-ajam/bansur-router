# Bansur Router

Bansur Router یک درگاه هوش مصنوعی محلی برای ابزارهای کدنویسی است. روی ماشین خودتان اجرا می‌شود و یک endpoint واحد سازگار با OpenAI — ‏`http://localhost:667/v1`‎ — را پیش روی همه ارائه‌دهندگانی که به آن متصل می‌کنید قرار می‌دهد.

ابزارتان را یک بار پیکربندی کنید. از آن پس، Bansur Router اتصال‌های ارائه‌دهندگان را پشت آن endpoint مدیریت می‌کند: کدام حساب به یک درخواست پاسخ می‌دهد، قالب درخواست چگونه ترجمه می‌شود، چقدر سهمیه باقی مانده است و وقتی یک ارائه‌دهنده پاسخ منفی می‌دهد چه اتفاقی می‌افتد. اشتراک‌هایی که از قبل برایشان پول می‌دهید اول استفاده می‌شوند، APIهای ارزان‌تر وقتی سهمیه تمام شود جای آن‌ها را می‌گیرند و لایه‌های رایگان در انتهای زنجیره، نشست را زنده نگه می‌دارند.

داشبورد در `http://localhost:667/dashboard` اجرا می‌شود؛ جایی که ارائه‌دهندگان را متصل می‌کنید، ترکیب‌های مدل می‌سازید و مصرف را زیر نظر می‌گیرید. کلیدها روی ماشین شما می‌مانند، ترافیک به‌صورت محلی مسیریابی می‌شود و این درگاه به‌صورت یک بسته npm و یک ایمیج Docker عرضه می‌شود که روی یک برنامه Next.js در حال اجرا روی Node.js ساخته شده است.

- **یک endpoint، یک کلید** — هر ارائه‌دهنده متصل، از هر ابزاری قابل دسترس است
- **بیش از 800 مدل** — به‌صورت زنده از طریق `GET /v1/models` فهرست می‌شوند
- **بازگشت 3 لایه** — اشتراک، سپس ارزان، سپس رایگان
- **ذخیره توکن داخلی** — خروجی ابزارها پیش از رسیدن به مدل فشرده می‌شوند
- **محلی‌محور (Local-first)** — کلیدها و ترافیک شما روی ماشین خودتان می‌مانند

نسخه فعلی: v1.0.5. به Node.js نسخه 20.9 یا بالاتر نیاز دارد.

## چرا Bansur Router

| مشکل | Bansur Router چه می‌کند |
| --- | --- |
| سهمیه اشتراک هر ماه استفاده‌نشده منقضی می‌شود | سهمیه را به‌ازای هر حساب پیگیری می‌کند و پیش از بازنشانی مصرفش می‌کند |
| محدودیت نرخ (Rate Limit) وسط کدنویسی شما را متوقف می‌کند | به‌صورت خودکار برمی‌گردد: اشتراک ← ارزان ← رایگان |
| خروجی ابزارهایی مثل `git diff`، `grep` و `ls` توکن می‌سوزانند | نتایج ابزار را با RTK فشرده می‌کند و در هر درخواست 20–40% توکن ذخیره می‌شود |
| هر ارائه‌دهنده ماهانه $20–50 می‌خواهد | وقتی لایه‌های ارزان و رایگان به‌اندازه کافی خوب‌اند، کار را به آن‌ها می‌فرستد |
| جابه‌جایی دستی بین ارائه‌دهندگان، جداگانه برای هر ابزار | به هر ابزار یک endpoint و یک کلید می‌دهد، با چرخش چندحسابه (round-robin) در پشت صحنه |

## شروع سریع

### 1. نصب و اجرا

```bash
npm install -g bansur-router
bansur-router
```

داشبورد در `http://localhost:667` باز می‌شود.

### 2. اتصال یک ارائه‌دهنده

**Dashboard → Providers → Connect** را باز کنید.

برای شروع به حساب پولی نیاز ندارید. **Kiro AI** را متصل کنید تا یک لایه رایگان با حدود 50 اعتبار در ماه بگیرید که Claude 4.5، GLM-5 و MiniMax را شامل می‌شود، یا **OpenCode Free** را متصل کنید که اصلاً به احراز هویت نیاز ندارد. اگر از قبل اشتراک یا کلید API دارید، به‌جای آن‌ها — یا در کنارشان — همان‌ها را متصل کنید.

### 3. ابزارتان را به Bansur Router وصل کنید

```text
Endpoint: http://localhost:667/v1
API Key:  copy it from the dashboard
Model:    kr/claude-sonnet-4.5
```

کل راه‌اندازی همین است. حالا ابزار شما از طریق آن یک endpoint به همه ارائه‌دهندگان متصل می‌رسد و Bansur Router تصمیم می‌گیرد هر درخواست کجا برود.

راه‌های دیگر اجرای Bansur Router — Docker و ساخت از منبع — در [راهنمای راه‌اندازی](#راهنمای-راه‌اندازی) پوشش داده شده‌اند.

## نحوه عملکرد

هر درخواست با قالبی که ابزار شما می‌فرستد می‌رسد، از درگاه عبور می‌کند و با قالبی که ارائه‌دهنده انتخاب‌شده انتظار دارد خارج می‌شود.

```text
Your CLI tool
  Claude Code, Codex, Cursor, Cline, ...
        |
        |  http://localhost:667/v1
        v
Bansur Router
  - RTK token saver (compress tool results)
  - Format translation (OpenAI <-> Claude <-> Gemini)
  - Quota tracking per account
  - Automatic OAuth token refresh
        |
        +--> Tier 1: SUBSCRIPTION
        |    Claude Code, Codex, GitHub Copilot
        |    (used first, while quota lasts)
        |
        +--> Tier 2: CHEAP
        |    GLM ($0.6 / 1M tokens), MiniMax ($0.20 / 1M tokens)
        |    (takes over when subscription quota runs out)
        |
        +--> Tier 3: FREE
             Kiro, OpenCode Free, Vertex AI ($300 credits
             for new Google Cloud accounts)
             (keeps the session running at no cost)
```

بازگشت خودکار است. وقتی لایه فعال خطای سهمیه یا محدودیت نرخ برمی‌گرداند، درخواست به‌جای این‌که در ویرایشگر شما شکست بخورد، در زنجیره پایین می‌رود.

## ویژگی‌های کلیدی

| ویژگی | چه می‌کند |
| --- | --- |
| ذخیره‌ساز توکن RTK | خروجی ابزارها — `git diff`، `grep`، `ls` و نتایج مشابه — را پیش از ارسال به مدل فشرده می‌کند و در هر درخواست 20–40% توکن ذخیره می‌شود |
| ذخیره‌ساز توکن Headroom | فشرده‌سازی بیشتری روی بافت (context) درخواست اعمال می‌کند و توکن‌هایی را که یک نشست طولانی مصرف می‌کند بیشتر کاهش می‌دهد |
| بازگشت هوشمند 3 لایه | هر درخواست را اشتراک ← ارزان ← رایگان مسیریابی می‌کند و هنگام اتمام سهمیه یا محدودیت نرخ، به‌صورت خودکار لایه را عوض می‌کند |
| پیگیری سهمیه به‌روز | مصرف زنده و زمان بازنشانی را به‌ازای هر حساب نشان می‌دهد تا سهمیه اشتراک پیش از انقضا مصرف شود، نه بعد از آن |
| ترجمه قالب | بین قالب‌های درخواست OpenAI، Claude و Gemini ترجمه می‌کند تا ابزاری که برای یک API ساخته شده بتواند از ارائه‌دهندگانی استفاده کند که برای API دیگری ساخته شده‌اند |
| پشتیبانی از چند حساب | چند حساب برای هر ارائه‌دهنده نگه می‌دارد و درخواست‌ها را با مسیریابی چرخشی (round-robin) میان آن‌ها توزیع می‌کند |
| بازسازی خودکار توکن | توکن‌های OAuth را به‌صورت خودکار تازه می‌کند تا ارائه‌دهندگان متصل بدون ورودهای مکرر، متصل بمانند |
| ترکیب‌های سفارشی | مدل‌های ارائه‌دهندگان و لایه‌های مختلف را در ترکیب‌های نام‌دار گروه‌بندی می‌کند که آن‌ها را به‌عنوان یک مدل واحد در ابزارتان انتخاب می‌کنید |
| ثبت درخواست | درخواست‌ها و پاسخ‌ها را برای بررسی ثبت می‌کند تا مشکلات مسیریابی و ارائه‌دهنده به‌جای سکوت، دیده شوند |
| همگام‌سازی ابری | پیکربندی شما را میان ماشین‌ها همگام می‌کند تا رایانه دوم با همان ارائه‌دهندگان و ترکیب‌ها شروع به کار کند |
| تحلیل استفاده | مصرف توکن را در طول زمان بر اساس ارائه‌دهنده، حساب و مدل تفکیک می‌کند |
| استقرار در هر جا | به‌صورت محلی، در Docker یا روی VPS اجرا می‌شود و در هر حالت همان داشبورد و همان endpoint را دارد |

- Codex
- GitHub Copilot
- Antigravity
- Gemini

| ارائه‌دهنده | لایه رایگان چه چیزی به شما می‌دهد |

هر endpointی که با قالب سازگار با OpenAI صحبت کند می‌تواند به‌عنوان ارائه‌دهنده متصل شود، بنابراین مدل‌هایی که خودتان سرو می‌دهید در همان زنجیره مسیریابی — و همان ترکیب‌ها — قرار می‌گیرند که ارائه‌دهندگان میزبانی‌شده قرار دارند.

## مرجع API

Bansur Router یک API سازگار با OpenAI روی endpoint محلی خود ارائه می‌دهد. با کلید API نمایش‌داده‌شده در داشبورد احراز هویت کنید.

### فهرست مدل‌ها

```text
GET /v1/models
```

هر مدلی را که در ارائه‌دهندگان متصل شما در دسترس است برمی‌گرداند — وقتی ارائه‌دهندگان رایج متصل باشند، بیش از 800 مدل.

### ایجاد Chat Completion

```text
POST /v1/chat/completions
Authorization: Bearer <dashboard API key>
```

```bash
curl http://localhost:667/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kr/claude-sonnet-4.5",
    "messages": [
      { "role": "user", "content": "Explain what this function does." }
    ]
  }'
```

شکل درخواست و پاسخ از قالب Chat Completions در OpenAI پیروی می‌کند. Bansur Router آن‌ها را به قالب بومی هر ارائه‌دهنده‌ای که زنجیره مسیریابی انتخاب کند ترجمه می‌کند.

URLهای کلیدی در یک نصب پیش‌فرض:

- داشبورد: `http://localhost:667/dashboard`
- پایه API: `http://localhost:667/v1`

## راهنمای راه‌اندازی

### اجرا با Docker

از یک نسخه checkout شده از این مخزن:

```bash
docker compose up -d
```

ایمیج‌های منتشرشده با نام `bansur/router` در Docker Hub و با نام `ghcr.io/mas-ajam/bansur-router` در GitHub Container Registry در دسترس‌اند. داشبورد و API روی پورت 667 سرو می‌شوند، درست مانند یک نصب محلی.

### اجرا از منبع

```bash
cp .env.example .env
npm install
npm run build
PORT=667 HOSTNAME=0.0.0.0 NEXT_PUBLIC_BASE_URL=http://localhost:667 npm run start
```

### اتصال یک ارائه‌دهنده

1. Bansur Router را شروع کنید و `http://localhost:667/dashboard` را باز کنید.
2. به **Providers** بروید و روی ارائه‌دهنده موردنظرتان **Connect** را انتخاب کنید.
3. برای ارائه‌دهندگان OAuth، ورود را در پنجره‌ای که باز می‌شود کامل کنید. برای ارائه‌دهندگان کلید API، کلیدی را که آن ارائه‌دهنده صادر کرده است بچسبانید.
4. یک درخواست بفرستید. سهمیه و مصرف ارائه‌دهنده هم‌زمان با مسیریابی درخواست‌ها در داشبورد ظاهر می‌شود.

اگر فقط می‌خواهید راه‌اندازی را بررسی کنید، با یک ارائه‌دهنده رایگان شروع کنید: هم Kiro AI و هم OpenCode Free بدون طرح پولی کار می‌کنند.

### ساخت یک ترکیب

یک ترکیب، فهرست مرتبی از مدل‌هاست که به‌عنوان یک مدل قابل انتخاب واحد در نظر گرفته می‌شود. مدل اشتراکتان را اول، یک مدل ارزان را دوم و یک مدل رایگان را آخر بگذارید، سپس آن ترکیب را در ابزارتان انتخاب کنید. وقتی مدل اول در دسترس نیست — سهمیه تمام شده، محدودیت نرخ اعمال شده یا خطا داده است — درخواست به‌صورت خودکار به مورد بعدی می‌رود.

### تغییر پورت

پورت 667 پیش‌فرض است، نه یک الزام.

```bash
bansur-router --port 8080
```

فرم کوتاه `-p` هم کار می‌کند و متغیر محیطی `PORT` پورت را برای استقرارهای منبع، Docker و سرور تنظیم می‌کند. اگر پورت را تغییر دادید، endpoint را در ابزارهایتان مطابق آن به‌روز کنید، مثلاً `http://localhost:8080/v1`. جدا کردن پورت همچنین ساده‌ترین راه برای اجرای Bansur Router در کنار سرویس محلی دیگری است که از قبل 667 را اشغال کرده است.

## سوالات متداول

### Bansur Router چیست؟

یک درگاه هوش مصنوعی محلی برای ابزارهای کدنویسی. یک endpoint سازگار با OpenAI را پیش روی همه ارائه‌دهندگان هوش مصنوعی شما قرار می‌دهد و هر درخواست را به بهترین ارائه‌دهنده در دسترس مسیریابی می‌کند، بنابراین ابزارهای شما یک پیکربندی واحد را نگه می‌دارند در حالی که ارائه‌دهندگان، حساب‌ها و سهمیه‌ها در پشت صحنه تغییر می‌کنند.

### آیا رایگان است؟

بله. خود Bansur Router رایگان و متن‌باز است و تحت مجوز MIT منتشر می‌شود. هزینه یک درخواست به ارائه‌دهنده‌ای بستگی دارد که به آن مسیریابی می‌شود: لایه‌های رایگانی مثل Kiro AI و OpenCode Free هیچ هزینه‌ای ندارند و برای بقیه، اشتراک‌ها و کلیدهای API خودتان را می‌آورید و مستقیم به همان ارائه‌دهندگان پرداخت می‌کنید، دقیقاً همان‌طور که بدون درگاه انجام می‌دادید.

### داده‌های من کجا قرار می‌گیرند؟

روی ماشین شما. Bansur Router محلی‌محور است: کلیدهای ارائه‌دهندگان به‌صورت محلی ذخیره می‌شوند، درخواست‌ها از نصب خودتان مسیریابی می‌شوند و کار درگاه این است که آن‌ها را به ارائه‌دهنده‌ای که انتخاب کرده‌اید فوروارد کند. پیش از اولین درخواست نیازی به ساخت حساب جداگانه نیست.

### از چه پورتی استفاده می‌کند؟

به‌صورت پیش‌فرض 667، هم برای داشبورد و هم برای API. هنگام شروع CLI با `--port` (یا `-p`) یا با متغیر محیطی `PORT` آن را تغییر دهید.

### با چه ابزارهایی کار می‌کند؟

Claude Code، OpenAI Codex، Cursor، Cline، OpenCode، Antigravity، GitHub Copilot، OpenClaw، Continue و RooCode مستقیماً پشتیبانی می‌شوند. هر ابزار دیگری که به شما اجازه دهد یک endpoint سفارشی سازگار با OpenAI و یک کلید API تنظیم کنید، با همان سه مقدار می‌تواند از آن استفاده کند.

### نکته‌ای برای کاربران Windows

پیش از به‌روزرسانی بسته سراسری npm، نمونه در حال اجرای Bansur Router را متوقف کنید. Windows فایل‌های یک نصب در حال اجرا را قفل می‌کند، بنابراین به‌روزرسانی‌ای که در حالی انجام شود که درگاه هنوز در حال اجراست، تا وقتی پردازش متوقف نشود شکست می‌خورد.

## عیب‌یابی

### پورت از قبل در حال استفاده است

چیزی روی ماشین شما از قبل روی 667 گوش می‌دهد، که اغلب یک پردازش قبلی Bansur Router است که هنوز در حال اجراست. آن پردازش را متوقف کنید یا روی پورت دیگری شروع کنید و ابزارهایتان را به آن وصل کنید:

```bash
bansur-router --port 8080
```

### یک ارائه‌دهنده متصل نمی‌شود

آن را از داشبورد دوباره متصل کنید: برای آن ارائه‌دهنده **Providers → Connect** و ورود یا وارد کردن کلید را دوباره کامل کنید. یک اتصال تازه جای نشست ذخیره‌شده را می‌گیرد و بازسازی خودکار توکن از آن پس آن را معتبر نگه می‌دارد.

### به‌روزرسانی در Windows شکست می‌خورد

اول نمونه در حال اجرا را متوقف کنید، سپس به‌روزرسانی را دوباره اجرا کنید. یک نصب در حال اجرا فایل‌های برنامه خودش را در Windows قفل می‌کند و همین مانع جایگزین شدن بسته سراسری npm می‌شود.

### درخواست‌ها پس از تغییر پورت شکست می‌خورند

ابزار شما هنوز به آدرس قدیمی اشاره می‌کند. endpoint آن را به پورت جدید به‌روز کنید — مثلاً `http://localhost:8080/v1` — و مطمئن شوید کلید API همان کلیدی است که در داشبورد نمونه‌ای که اکنون در حال اجراست نمایش داده می‌شود.
