# Bansur Router

Bansur Router — это локальный AI-шлюз для инструментов программирования. Он работает на вашей собственной машине и предоставляет единый эндпоинт, совместимый с OpenAI — `http://localhost:667/v1` — перед всеми провайдерами, которых вы к нему подключаете.

Настройте свой инструмент один раз. После этого Bansur Router берёт на себя подключения к провайдерам за этим эндпоинтом: какой аккаунт отвечает на запрос, как переводится формат запроса, сколько квоты осталось и что происходит, когда провайдер отказывает. Подписки, за которые вы уже платите, используются в первую очередь, более дешёвые API принимают эстафету, когда они заканчиваются, а бесплатные тарифы поддерживают сессию в конце цепочки.

Панель управления работает по адресу `http://localhost:667/dashboard`, где вы подключаете провайдеров, собираете комбинации моделей и следите за использованием. Ключи остаются на вашей машине, трафик маршрутизируется локально, а шлюз поставляется как пакет npm и образ Docker, построенные на приложении Next.js, работающем на Node.js.

- **Один эндпоинт, один ключ** — все подключённые провайдеры, доступные из каждого инструмента
- **Более 800 моделей** — актуальный список через `GET /v1/models`
- **Резервирование в 3 уровня** — Подписка, затем Дешёвый, затем Бесплатный
- **Экономия токенов встроена** — выходные данные инструментов сжимаются до того, как достигнут модели
- **Локальность прежде всего** — ваши ключи и ваш трафик остаются на вашей машине

Текущий релиз: v1.0.5. Требуется Node.js 20.9 или новее.

## Почему Bansur Router?

| Проблема | Что делает Bansur Router |
| --- | --- |
| Квота подписки каждый месяц сгорает неиспользованной | Отслеживает квоту по каждому аккаунту и расходует её до сброса |
| Лимит запросов останавливает вас посреди сессии программирования | Автоматически переходит по цепочке: Подписка → Дешёвый → Бесплатный |
| Выходные данные инструментов, такие как `git diff`, `grep` и `ls`, сжигают токены | Сжимает результаты инструментов с помощью RTK, экономя 20–40% токенов на запрос |
| Каждый провайдер хочет $20–50 в месяц | Направляет работу на дешёвые и бесплатные уровни, когда их достаточно |
| Приходится вручную переключать провайдеров отдельно для каждого инструмента | Даёт каждому инструменту один эндпоинт и один ключ, а за ними — round-robin между несколькими аккаунтами |

## Быстрый старт

### 1. Установка и запуск

```bash
npm install -g bansur-router
bansur-router
```

Панель управления открывается по адресу `http://localhost:667`.

### 2. Подключение провайдера

Откройте **Панель управления → Провайдеры → Подключить**.

Вам не нужен платный аккаунт, чтобы начать. Подключите **Kiro AI** ради бесплатного тарифа примерно на 50 кредитов в месяц, который включает Claude 4.5, GLM-5 и MiniMax, или подключите **OpenCode Free**, которому вообще не нужна аутентификация. Если у вас уже есть подписки или API-ключи, подключите их вместо этого — или в дополнение.

### 3. Направьте ваш инструмент на Bansur Router

```text
Endpoint: http://localhost:667/v1
API Key:  copy it from the dashboard
Model:    kr/claude-sonnet-4.5
```

Это вся настройка. Теперь инструмент достигает всех подключённых провайдеров через один эндпоинт, а Bansur Router решает, куда идёт каждый запрос.

Другие способы запуска Bansur Router — Docker и сборка из исходного кода — описаны в [Руководстве по установке](#руководство-по-установке).

## Как это работает

Каждый запрос приходит в формате, который отправляет ваш инструмент, проходит через шлюз и уходит в формате, который ожидает выбранный провайдер.

```text
Your CLI tool
  Claude Code, Codex, Cursor, Cline, ...
        |
        |  http://localhost:667/v1
        v
Bansur Router
  - RTK token saver (compress tool results)
  - Format translation (OpenAI <-> Claude <-> Gemini)
  - Quota tracking per account
  - Automatic OAuth token refresh
        |
        +--> Tier 1: SUBSCRIPTION
        |    Claude Code, Codex, GitHub Copilot
        |    (used first, while quota lasts)
        |
        +--> Tier 2: CHEAP
        |    GLM ($0.6 / 1M tokens), MiniMax ($0.20 / 1M tokens)
        |    (takes over when subscription quota runs out)
        |
        +--> Tier 3: FREE
             Kiro, OpenCode Free, Vertex AI ($300 credits
             for new Google Cloud accounts)
             (keeps the session running at no cost)
```

Резервирование автоматическое. Когда активный уровень возвращает ошибку квоты или лимит запросов, запрос спускается по цепочке вместо того, чтобы завершиться ошибкой в вашем редакторе.

## Ключевые возможности

| Возможность | Что она делает |
| --- | --- |
| Экономия токенов RTK | Сжимает выходные данные инструментов — `git diff`, `grep`, `ls` и подобные результаты — до отправки модели, экономя 20–40% токенов на запрос |
| Экономия токенов Headroom | Применяет дополнительное сжатие к контексту запроса, ещё сильнее сокращая токены, которые потребляет длинная сессия |
| Умное трёхуровневое резервирование | Маршрутизирует каждый запрос Подписка → Дешёвый → Бесплатный, автоматически переключая уровни при исчерпании квоты или лимитах запросов |
| Отслеживание квот в реальном времени | Показывает актуальное использование и время сброса по каждому аккаунту, чтобы квота подписки расходовалась до истечения, а не после |
| Трансляция форматов | Переводит между форматами запросов OpenAI, Claude и Gemini, чтобы инструмент, созданный для одного API, мог использовать провайдеров, созданных для другого |
| Поддержка нескольких аккаунтов | Хранит несколько аккаунтов на провайдера и распределяет запросы между ними по round-robin |
| Автоматическое обновление токенов | Автоматически обновляет OAuth-токены, чтобы подключённые провайдеры оставались подключёнными без повторных входов |
| Пользовательские комбо | Группирует модели разных провайдеров и уровней в именованные комбинации, которые вы выбираете как одну модель в своём инструменте |
| Журналирование запросов | Записывает запросы и ответы для проверки, что делает проблемы маршрутизации и провайдеров видимыми, а не тихими |
| Облачная синхронизация | Синхронизирует вашу конфигурацию между машинами, чтобы второй компьютер начинал с тех же провайдеров и комбо |
| Аналитика использования | Детализирует использование токенов во времени по провайдерам, аккаунтам и моделям |
| Развёртывание где угодно | Работает локально, в Docker или на VPS, с той же панелью управления и эндпоинтом в каждом случае |

## Справочник API

Bansur Router предоставляет API, совместимый с OpenAI, на своём локальном эндпоинте. Аутентифицируйтесь с помощью API-ключа, показанного в панели управления.

### Список моделей

```text
GET /v1/models
```

Возвращает все модели, доступные у ваших подключённых провайдеров, — более 800 моделей, как только подключены распространённые провайдеры.

### Создание завершения чата

```text
POST /v1/chat/completions
Authorization: Bearer <dashboard API key>
```

```bash
curl http://localhost:667/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kr/claude-sonnet-4.5",
    "messages": [
      { "role": "user", "content": "Explain what this function does." }
    ]
  }'
```

Форма запроса и ответа следует формату завершений чата OpenAI. Bansur Router переводит их в собственный формат того провайдера, которого выберет цепочка маршрутизации.

Ключевые URL при установке по умолчанию:

- Панель управления: `http://localhost:667/dashboard`
- База API: `http://localhost:667/v1`

## Руководство по установке

### Запуск через Docker

Из копии этого репозитория:

```bash
docker compose up -d
```

Опубликованные образы доступны как `bansur/router` на Docker Hub и как `ghcr.io/mas-ajam/bansur-router` в GitHub Container Registry. Панель управления и API обслуживаются на порту 667, как и при локальной установке.

### Запуск из исходного кода

```bash
cp .env.example .env
npm install
npm run build
PORT=667 HOSTNAME=0.0.0.0 NEXT_PUBLIC_BASE_URL=http://localhost:667 npm run start
```

### Подключение провайдера

1. Запустите Bansur Router и откройте `http://localhost:667/dashboard`.
2. Перейдите в **Провайдеры** и выберите **Подключить** у нужного провайдера.
3. Для провайдеров OAuth завершите вход в открывшемся окне. Для провайдеров с API-ключом вставьте ключ, выданный этим провайдером.
4. Отправьте запрос. Квота и использование провайдера появляются в панели управления по мере маршрутизации запросов.

Начните с бесплатного провайдера, если хотите только проверить настройку: Kiro AI и OpenCode Free работают без платного тарифа.

### Создание комбо

Комбо — это упорядоченный список моделей, рассматриваемый как одна выбираемая модель. Поставьте первой вашу модель по подписке, второй — дешёвую модель, последней — бесплатную, а затем выберите комбо в своём инструменте. Когда первая модель недоступна — квота исчерпана, достигнут лимит запросов или ошибка, — запрос автоматически переходит к следующей записи.

### Изменение порта

Порт 667 — это значение по умолчанию, а не требование.

```bash
bansur-router --port 8080
```

Короткая форма `-p` тоже работает, а переменная окружения `PORT` задаёт порт для развёртываний из исходного кода, Docker и на сервере. Если вы измените порт, обновите эндпоинт в ваших инструментах соответственно, например `http://localhost:8080/v1`. Разделение портов — также самый простой способ запускать Bansur Router рядом с другим локальным сервисом, который уже занимает 667.

## Часто задаваемые вопросы

### Что такое Bansur Router?

Локальный AI-шлюз для инструментов программирования. Он ставит один эндпоинт, совместимый с OpenAI, перед всеми вашими AI-провайдерами и направляет каждый запрос лучшему доступному, чтобы ваши инструменты сохраняли единственную конфигурацию, пока провайдеры, аккаунты и квоты меняются за ней.

### Это бесплатно?

Да. Сам Bansur Router бесплатен и открыт под лицензией MIT. Стоимость запроса зависит от провайдера, к которому он маршрутизируется: бесплатные тарифы, такие как Kiro AI и OpenCode Free, ничего не стоят, а для остальных вы приносите свои подписки и API-ключи и платите этим провайдерам напрямую, ровно так, как делали бы без шлюза.

### Где живут мои данные?

На вашей машине. Bansur Router локален прежде всего: ключи провайдеров хранятся локально, запросы маршрутизируются из вашей собственной установки, а работа шлюза — пересылать их провайдеру, которого вы выбрали. Отдельный аккаунт, который нужно создать до первого запроса, не требуется.

### Какой порт он использует?

667 по умолчанию, и для панели управления, и для API. Измените его с помощью `--port` (или `-p`) при запуске CLI или переменной окружения `PORT`.

### С какими инструментами он работает?

Claude Code, OpenAI Codex, Cursor, Cline, OpenCode, Antigravity, GitHub Copilot, OpenClaw, Continue и RooCode поддерживаются напрямую. Любой другой инструмент, позволяющий задать пользовательский эндпоинт, совместимый с OpenAI, и API-ключ, может использовать его с теми же тремя значениями.

### Примечание для пользователей Windows

Остановите работающий экземпляр Bansur Router перед обновлением глобального пакета npm. Windows блокирует файлы работающей установки, поэтому обновление, предпринятое, пока шлюз ещё работает, завершится ошибкой, пока процесс не остановлен.

## Устранение неполадок

### Порт уже используется

Что-то на вашей машине уже слушает 667, часто более ранний процесс Bansur Router, который всё ещё работает. Остановите этот процесс или запуститесь на другом порту и направьте ваши инструменты на него:

```bash
bansur-router --port 8080
```

### Провайдер не подключается

Переподключите его из панели управления: **Провайдеры → Подключить** для этого провайдера, и завершите вход или ввод ключа заново. Новое подключение заменяет сохранённую сессию, а автоматическое обновление токенов сохраняет её действительной в дальнейшем.

### Обновление завершается ошибкой в Windows

Сначала остановите работающий экземпляр, затем снова запустите обновление. Работающая установка блокирует свои собственные программные файлы в Windows, что не даёт заменить глобальный пакет npm.

### Запросы завершаются ошибкой после смены порта

Ваш инструмент всё ещё указывает на старый адрес. Обновите его эндпоинт на новый порт — например `http://localhost:8080/v1` — и убедитесь, что API-ключ — тот, что показан в панели управления экземпляра, работающего сейчас.
