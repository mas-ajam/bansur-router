# Bansur Router

Bansur Router คือเกตเวย์ AI บนเครื่องของคุณสำหรับเครื่องมือเขียนโค้ด มันทำงานบนเครื่องของคุณเองและนำเสนอปลายทางที่เข้ากันได้กับ OpenAI เพียงหนึ่งเดียว — `http://localhost:667/v1` — ไว้ด้านหน้าของผู้ให้บริการทุกรายที่คุณเชื่อมต่อเข้ามา

ตั้งค่าเครื่องมือของคุณเพียงครั้งเดียว หลังจากนั้น Bansur Router จะจัดการการเชื่อมต่อผู้ให้บริการทั้งหมดที่อยู่หลังปลายทางนั้น: บัญชีใดเป็นผู้ตอบคำขอ การแปลงรูปแบบคำขอเป็นอย่างไร โควตาเหลืออยู่เท่าใด และจะเกิดอะไรขึ้นเมื่อผู้ให้บริการปฏิเสธ สมาชิกที่คุณจ่ายเงินอยู่แล้วจะถูกใช้ก่อน ส่วน API ที่ถูกกว่าจะรับช่วงต่อเมื่อโควตาหมด และระดับฟรีจะช่วยให้เซสชันดำเนินต่อไปได้จนสุดปลายห่วงโซ่

แดชบอร์ดทำงานที่ `http://localhost:667/dashboard` ซึ่งเป็นที่ที่คุณเชื่อมต่อผู้ให้บริการ สร้างชุดผสมโมเดล และเฝ้าดูการใช้งาน คีย์ของคุณอยู่บนเครื่องของคุณ ทราฟฟิกถูกกำหนดเส้นทางภายในเครื่อง และเกตเวย์นี้จัดส่งเป็นแพ็กเกจ npm และอิมเมจ Docker ที่สร้างบนแอป Next.js ซึ่งทำงานบน Node.js

- **หนึ่งปลายทาง หนึ่งคีย์** — ผู้ให้บริการที่เชื่อมต่อทุกราย เข้าถึงได้จากทุกเครื่องมือ
- **โมเดลมากกว่า 800 โมเดล** — แสดงรายการแบบสดผ่าน `GET /v1/models`
- **การสลับสำรอง 3 ระดับ** — สมาชิก จากนั้นราคาถูก จากนั้นฟรี
- **ประหยัดโทเค็นในตัว** — ผลลัพธ์จากเครื่องมือจะถูกบีบอัดก่อนส่งถึงโมเดล
- **Local-first** — คีย์และทราฟฟิกของคุณอยู่บนเครื่องของคุณ

เวอร์ชันปัจจุบัน: v1.0.5 ต้องการ Node.js 20.9 ขึ้นไป

## ทำไมต้อง Bansur Router

| ปัญหา | Bansur Router ทำอะไร |
| --- | --- |
| โควตาสมาชิกหมดอายุโดยไม่ได้ใช้ทุกเดือน | ติดตามโควตาแยกตามบัญชีและใช้ให้หมดก่อนที่จะรีเซ็ต |
| Rate Limit หยุดคุณระหว่างเขียนโค้ด | สลับสำรองโดยอัตโนมัติ: สมาชิก → ราคาถูก → ฟรี |
| ผลลัพธ์จากเครื่องมืออย่าง `git diff`, `grep` และ `ls` เผาผลาญโทเค็น | บีบอัดผลลัพธ์จากเครื่องมือด้วย RTK ประหยัดโทเค็น 20–40% ต่อคำขอ |
| ผู้ให้บริการทุกรายต้องการ $20–50 ต่อเดือน | ส่งงานไปยังระดับที่ถูกกว่าและฟรีเมื่อคุณภาพเพียงพอ |
| ต้องสลับผู้ให้บริการด้วยตนเองแยกกันสำหรับแต่ละเครื่องมือ | ให้ทุกเครื่องมือใช้หนึ่งปลายทางและหนึ่งคีย์ โดยมี Round-robin หลายบัญชีอยู่เบื้องหลัง |

## เริ่มต้นใช้งาน

### 1. ติดตั้งและรัน

```bash
npm install -g bansur-router
bansur-router
```

แดชบอร์ดจะเปิดที่ `http://localhost:667`

### 2. เชื่อมต่อผู้ให้บริการ

เปิด **Dashboard → Providers → Connect**

คุณไม่จำเป็นต้องมีบัญชีแบบชำระเงินเพื่อเริ่มต้น เชื่อมต่อ **Kiro AI** เพื่อรับระดับฟรีประมาณ 50 เครดิตต่อเดือน ซึ่งรวม Claude 4.5, GLM-5 และ MiniMax ไว้ด้วย หรือเชื่อมต่อ **OpenCode Free** ซึ่งไม่ต้องมีการยืนยันตัวตนเลย หากคุณมีสมาชิกหรือ API Key อยู่แล้ว ให้เชื่อมต่อสิ่งเหล่านั้นแทน — หรือควบคู่กันไปก็ได้

### 3. ชี้เครื่องมือของคุณมาที่ Bansur Router

```text
Endpoint: http://localhost:667/v1
API Key:  copy it from the dashboard
Model:    kr/claude-sonnet-4.5
```

การตั้งค่ามีเพียงเท่านี้ ตอนนี้เครื่องมือของคุณเข้าถึงผู้ให้บริการที่เชื่อมต่อทุกรายผ่านปลายทางเดียว และ Bansur Router จะตัดสินใจว่าคำขอแต่ละรายการจะไปที่ใด

วิธีอื่นในการรัน Bansur Router — Docker และการ build จากซอร์สโค้ด — อธิบายไว้ใน[คู่มือการตั้งค่า](#คู่มือการตั้งค่า)

## วิธีการทำงาน

คำขอทุกรายการมาถึงในรูปแบบที่เครื่องมือของคุณส่ง ผ่านเกตเวย์ และออกไปในรูปแบบที่ผู้ให้บริการซึ่งถูกเลือกไว้คาดหวัง

```text
Your CLI tool
  Claude Code, Codex, Cursor, Cline, ...
        |
        |  http://localhost:667/v1
        v
Bansur Router
  - RTK token saver (compress tool results)
  - Format translation (OpenAI <-> Claude <-> Gemini)
  - Quota tracking per account
  - Automatic OAuth token refresh
        |
        +--> Tier 1: SUBSCRIPTION
        |    Claude Code, Codex, GitHub Copilot
        |    (used first, while quota lasts)
        |
        +--> Tier 2: CHEAP
        |    GLM ($0.6 / 1M tokens), MiniMax ($0.20 / 1M tokens)
        |    (takes over when subscription quota runs out)
        |
        +--> Tier 3: FREE
             Kiro, OpenCode Free, Vertex AI ($300 credits
             for new Google Cloud accounts)
             (keeps the session running at no cost)
```

การสลับสำรองเป็นไปโดยอัตโนมัติ เมื่อระดับที่กำลังใช้งานอยู่ส่งคืนข้อผิดพลาดโควตาหมดหรือ Rate Limit คำขอจะเลื่อนลงไปตามห่วงโซ่แทนที่จะล้มเหลวในโปรแกรมแก้ไขโค้ดของคุณ

| Auto Token Refresh | รีเฟรชโทเค็น OAuth โดยอัตโนมัติ เพื่อให้ผู้ให้บริการที่เชื่อมต่อแล้วยังคงเชื่อมต่ออยู่โดยไม่ต้องเข้าสู่ระบบซ้ำ |
| Custom Combos | จัดกลุ่มโมเดลจากผู้ให้บริการและระดับต่าง ๆ เป็นชุดผสมที่มีชื่อ ซึ่งคุณเลือกใช้เสมือนเป็นโมเดลเดียวในเครื่องมือของคุณ |
| Request Logging | บันทึกคำขอและการตอบกลับไว้เพื่อตรวจสอบ ทำให้ปัญหาการกำหนดเส้นทางและผู้ให้บริการมองเห็นได้แทนที่จะเงียบหาย |
| Cloud Sync | ซิงค์การกำหนดค่าของคุณข้ามเครื่อง เพื่อให้คอมพิวเตอร์เครื่องที่สองเริ่มต้นจากผู้ให้บริการและชุดผสมเดียวกัน |
| Usage Analytics | แยกแยะการใช้โทเค็นตามช่วงเวลา ตามผู้ให้บริการ บัญชี และโมเดล |
| Deploy Anywhere | ทำงานบนเครื่องของคุณ ใน Docker หรือบน VPS ด้วยแดชบอร์ดและปลายทางเดียวกันในทุกกรณี |

## ผู้ให้บริการที่รองรับ

ผู้ให้บริการที่เชื่อมต่อแล้วเปิดให้ใช้โมเดลมากกว่า 800 โมเดลผ่านปลายทางเดียว เรียก `GET /v1/models` กับอินสแตนซ์ที่กำลังทำงานอยู่เพื่อดูรายการที่แน่นอนสำหรับการเชื่อมต่อของคุณ

- Codex
- GitHub Copilot
- Antigravity
- Gemini
- iFlow
- Windsurf
- Kiro

## เอกสารอ้างอิง API

Bansur Router เปิด API ที่เข้ากันได้กับ OpenAI บนปลายทางภายในเครื่อง ยืนยันตัวตนด้วย API Key ที่แสดงในแดชบอร์ด

### แสดงรายการโมเดล

```text
GET /v1/models
```

ส่งคืนโมเดลทุกตัวที่มีอยู่ในผู้ให้บริการที่คุณเชื่อมต่อ — มากกว่า 800 โมเดลเมื่อเชื่อมต่อผู้ให้บริการทั่วไปแล้ว

### สร้าง Chat Completion

```text
POST /v1/chat/completions
Authorization: Bearer <dashboard API key>
```

```bash
curl http://localhost:667/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kr/claude-sonnet-4.5",
    "messages": [
      { "role": "user", "content": "Explain what this function does." }
    ]
  }'
```

รูปแบบคำขอและการตอบกลับเป็นไปตามรูปแบบ Chat Completions ของ OpenAI Bansur Router จะแปลมันให้เป็นรูปแบบดั้งเดิมของผู้ให้บริการรายใดก็ตามที่ห่วงโซ่การกำหนดเส้นทางเลือก

URL หลักในการติดตั้งเริ่มต้น:

- แดชบอร์ด: `http://localhost:667/dashboard`
- API base: `http://localhost:667/v1`

## คู่มือการตั้งค่า

### รันด้วย Docker

จากโฟลเดอร์ที่เช็กเอาต์รีโปนี้ไว้:

```bash
docker compose up -d
```

อิมเมจที่เผยแพร่มีให้ใช้ในชื่อ `bansur/router` บน Docker Hub และ `ghcr.io/mas-ajam/bansur-router` บน GitHub Container Registry แดชบอร์ดและ API ให้บริการบนพอร์ต 667 เช่นเดียวกับการติดตั้งบนเครื่อง

### รันจากซอร์สโค้ด

```bash
cp .env.example .env
npm install
npm run build
PORT=667 HOSTNAME=0.0.0.0 NEXT_PUBLIC_BASE_URL=http://localhost:667 npm run start
```

### เชื่อมต่อผู้ให้บริการ

1. เริ่ม Bansur Router และเปิด `http://localhost:667/dashboard`
2. ไปที่ **Providers** และเลือก **Connect** บนผู้ให้บริการที่คุณต้องการ
3. สำหรับผู้ให้บริการ OAuth ให้เข้าสู่ระบบให้เสร็จในหน้าต่างที่เปิดขึ้น สำหรับผู้ให้บริการ API Key ให้วางคีย์ที่ผู้ให้บริการรายนั้นออกให้
4. ส่งคำขอ โควตาและการใช้งานของผู้ให้บริการจะปรากฏในแดชบอร์ดขณะที่คำขอถูกกำหนดเส้นทาง

เริ่มต้นด้วยผู้ให้บริการฟรีหากคุณต้องการเพียงตรวจสอบว่าการตั้งค่าถูกต้อง: ทั้ง Kiro AI และ OpenCode Free ใช้งานได้โดยไม่ต้องมีแผนแบบชำระเงิน

### สร้าง Combo

Combo คือรายการโมเดลที่มีลำดับและถือเป็นโมเดลเดียวที่เลือกใช้ได้ ให้ใส่โมเดลสมาชิกของคุณไว้แรกสุด โมเดลราคาถูกไว้ที่สอง และโมเดลฟรีไว้สุดท้าย จากนั้นเลือก Combo นั้นในเครื่องมือของคุณ เมื่อโมเดลแรกใช้ไม่ได้ — โควตาหมด ติด Rate Limit หรือเกิดข้อผิดพลาด — คำขอจะย้ายไปยังรายการถัดไปโดยอัตโนมัติ

### เปลี่ยนพอร์ต

พอร์ต 667 เป็นค่าเริ่มต้น ไม่ใช่ข้อบังคับ

```bash
bansur-router --port 8080
```

รูปแบบสั้น `-p` ก็ใช้ได้เช่นกัน และตัวแปรสภาพแวดล้อม `PORT` ใช้กำหนดพอร์ตสำหรับการปรับใช้แบบซอร์สโค้ด Docker และเซิร์ฟเวอร์ หากคุณเปลี่ยนพอร์ต ให้อัปเดตปลายทางในเครื่องมือของคุณให้ตรงกัน เช่น `http://localhost:8080/v1` การแยกพอร์ตยังเป็นวิธีที่ง่ายที่สุดในการรัน Bansur Router ควบคู่กับบริการอื่นบนเครื่องที่ใช้งาน 667 อยู่แล้ว

## คำถามที่พบบ่อย

### Bansur Router คืออะไร?

เกตเวย์ AI บนเครื่องสำหรับเครื่องมือเขียนโค้ด มันวางปลายทางที่เข้ากันได้กับ OpenAI หนึ่งเดียวไว้ด้านหน้าของผู้ให้บริการ AI ทั้งหมดของคุณ และกำหนดเส้นทางคำขอแต่ละรายการไปยังผู้ให้บริการที่ดีที่สุดที่มีอยู่ ดังนั้นเครื่องมือของคุณจึงคงการกำหนดค่าเดียวไว้ ขณะที่ผู้ให้บริการ บัญชี และโควตาเปลี่ยนแปลงอยู่เบื้องหลัง

### ฟรีหรือไม่?

ฟรี Bansur Router เองนั้นฟรีและเป็นโอเพนซอร์สภายใต้ลิขสิทธิ์ MIT ค่าใช้จ่ายของคำขอขึ้นอยู่กับผู้ให้บริการที่คำขอถูกส่งไป: ระดับฟรีอย่าง Kiro AI และ OpenCode Free ไม่มีค่าใช้จ่าย ส่วนที่เหลือคุณนำสมาชิกและ API Key ของคุณเองมาใช้ และจ่ายให้ผู้ให้บริการเหล่านั้นโดยตรง เหมือนกับที่คุณทำโดยไม่มีเกตเวย์

### ข้อมูลของฉันอยู่ที่ไหน?

บนเครื่องของคุณ Bansur Router เป็นแบบ Local-first: คีย์ของผู้ให้บริการถูกจัดเก็บภายในเครื่อง คำขอถูกกำหนดเส้นทางจากการติดตั้งของคุณเอง และงานของเกตเวย์คือส่งต่อคำขอเหล่านั้นไปยังผู้ให้บริการที่คุณเลือก ไม่จำเป็นต้องสร้างบัญชีแยกต่างหากก่อนส่งคำขอแรก

### ใช้พอร์ตใด?

667 เป็นค่าเริ่มต้น สำหรับทั้งแดชบอร์ดและ API เปลี่ยนได้ด้วย `--port` (หรือ `-p`) เมื่อเริ่ม CLI หรือด้วยตัวแปรสภาพแวดล้อม `PORT`

### ใช้กับเครื่องมือใดได้บ้าง?

Claude Code, OpenAI Codex, Cursor, Cline, OpenCode, Antigravity, GitHub Copilot, OpenClaw, Continue และ RooCode รองรับโดยตรง เครื่องมืออื่นใดที่ให้คุณตั้งค่าปลายทางที่เข้ากันได้กับ OpenAI แบบกำหนดเองและ API Key ได้ ก็สามารถใช้ด้วยค่าสามค่าเดียวกันได้

### หมายเหตุสำหรับผู้ใช้ Windows

หยุดอินสแตนซ์ Bansur Router ที่กำลังทำงานอยู่ก่อนอัปเดตแพ็กเกจ npm แบบ global Windows จะล็อกไฟล์ของการติดตั้งที่กำลังทำงาน ดังนั้นการอัปเดตที่พยายามทำขณะที่เกตเวย์ยังทำงานอยู่จะล้มเหลวจนกว่ากระบวนการจะถูกหยุด

## การแก้ไขปัญหา

### พอร์ตถูกใช้งานอยู่

มีบางอย่างบนเครื่องของคุณกำลังฟังอยู่ที่พอร์ต 667 อยู่แล้ว ซึ่งมักเป็นกระบวนการ Bansur Router ก่อนหน้านี้ที่ยังทำงานอยู่ ให้หยุดกระบวนการนั้น หรือเริ่มบนพอร์ตอื่นและชี้เครื่องมือของคุณไปที่นั่น:

```bash
bansur-router --port 8080
```

### ผู้ให้บริการเชื่อมต่อไม่สำเร็จ

เชื่อมต่อใหม่จากแดชบอร์ด: **Providers → Connect** สำหรับผู้ให้บริการรายนั้น และเข้าสู่ระบบหรือป้อนคีย์ให้เสร็จอีกครั้ง การเชื่อมต่อใหม่จะแทนที่เซสชันที่จัดเก็บไว้ และการรีเฟรชโทเค็นอัตโนมัติจะรักษาความถูกต้องของมันต่อไป

### การอัปเดตล้มเหลวบน Windows

หยุดอินสแตนซ์ที่กำลังทำงานอยู่ก่อน แล้วเรียกการอัปเดตอีกครั้ง การติดตั้งที่กำลังทำงานจะล็อกไฟล์โปรแกรมของตัวเองบน Windows ซึ่งขัดขวางไม่ให้แพ็กเกจ npm แบบ global ถูกแทนที่

### คำขอล้มเหลวหลังจากเปลี่ยนพอร์ต

เครื่องมือของคุณยังชี้ไปยังที่อยู่เก่า ให้อัปเดตปลายทางเป็นพอร์ตใหม่ — เช่น `http://localhost:8080/v1` — และยืนยันว่า API Key เป็นคีย์ที่แสดงในแดชบอร์ดของอินสแตนซ์ที่กำลังทำงานอยู่ตอนนี้
